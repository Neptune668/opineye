# 舆情分析平台 · 前后端分离开发文档

> 版本：v1.1　|　更新日期：2026-08-26
> 适用范围：2.2 舆情分析平台（Web 控制台 + 分析服务 + 配置文件 + 示例数据 + 接口说明 + 完整分析案例）

---

## 1. 项目概述

面向指定主题的舆情分析平台，从「公开信息、多媒体内容、内部沉淀数据」三个方向并行收集信息，汇总生成结构化舆情报告。交付形式为可运行的 Web 控制台、分析服务、配置文件、示例数据、接口说明，以及至少一个完整主题的分析案例。

### 1.1 核心设计原则

| 原则             | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| 前后端分离       | 前端 SPA 通过 REST API + WebSocket 与后端通信，二者独立开发、独立部署 |
| 单功能应用进程化 | 主题检索、多媒体检索、论坛采集、洞察分析、报告生成等以**独立子进程**运行，可单独启停 |
| 文件即存储       | 全部数据以 JSON/Markdown/日志文件落盘，无数据库依赖，便于示例数据与验收演示 |
| 状态可观测       | 系统 / 应用 / 采集三级状态 + 标准/错误输出，均通过接口与实时消息暴露 |
| 防御性编程       | 文件读写加锁、子进程异常兜底、WebSocket 自动重连，确保单点故障不影响整体 |

### 1.2 用户角色

| 角色       | 权限范围                                             |
| ---------- | ---------------------------------------------------- |
| 操作用户   | 启动/停止单功能应用、发起主题检索、查看输出结果       |
| 报告查看人 | 查看已生成报告、图谱结果、论坛日志和来源证据         |
| 系统管理员 | 维护系统配置、查看系统状态、启停整体服务、查看运行日志 |

> 当前版本不做登录认证，角色区分体现在页面功能可见性上；后续可扩展 RBAC 中间件。

**通信约定**

- 读状态、查输出、查配置 → REST `GET`
- 发起动作（启停、检索、更新配置）→ REST `POST`
- 状态变化、日志流、错误 → WebSocket 服务端主动推送
- 前端不轮询：进入页面时先 `GET` 快照，再通过 WebSocket 订阅增量更新

## 5. 状态枚举定义

所有状态值以字符串常量定义，前后端共享同一枚举语义。

### 5.1 单功能应用状态

| 状态       | 含义                     | 允许转换               |
| ---------- | ------------------------ | ---------------------- |
| `stopped`  | 已停止，未运行           | → `starting`           |
| `starting` | 正在启动中               | → `running` / `failed` |
| `running`  | 正常运行中               | → `stopping` / `failed`|
| `stopping` | 正在停止中               | → `stopped`            |
| `failed`   | 进程异常退出             | → `starting`（重启）   |

### 5.2 论坛采集状态

| 状态      | 含义               | 允许转换                |
| --------- | ------------------ | ----------------------- |
| `idle`    | 空闲，未启动       | → `running`             |
| `running` | 采集中             | → `stopped` / `failed`  |
| `stopped` | 已停止             | → `running`             |
| `failed`  | 采集异常           | → `running`（重启）     |

### 5.3 系统状态

| 状态             | 含义             | 允许转换                  |
| ---------------- | ---------------- | ------------------------- |
| `offline`        | 服务未启动       | → `starting`              |
| `starting`       | 服务启动中       | → `online` / `offline`    |
| `online`         | 服务正常运行     | → `shutting_down`         |
| `shutting_down`  | 服务关闭中       | → `offline`               |

## 6. 数据存储设计

数据根目录统一为 `backend/data/`（记为 `DATA_ROOT`），全部相对路径基于此。

**数据目录初始化**：服务首次启动时，`store.py` 检查 `DATA_ROOT` 下必要子目录是否存在，不存在则自动创建（`runtime/apps/`、`runtime/forum/history/`、`reports/`、`graphs/`、`outputs/`），`config.json` 不存在则写入默认模板。

### 6.1 `config.json` — 系统配置

```json
{
  "system": {
    "name": "舆情分析平台",
    "default_apps": ["search", "media", "forum", "insight", "report"]
  },
  "collection": {
    "forum": { "interval_seconds": 300, "max_pages": 10 },
    "default_source_types": ["news", "image", "video", "forum_post", "internal_data"]
  },
  "analysis": { "insight_enabled": true, "sentiment_mode": "rule_based" },
  "runtime": { "log_level": "INFO", "output_retention_days": 30 }
}
```

**配置版本化**：每次 `POST /api/config` 保存前，将当前 `config.json` 备份为 `config.json.bak`，防止误操作后可手动回滚。

### 6.2 运行与输出文件

| 路径                                | 内容                    | 说明                            |
| ----------------------------------- | ----------------------- | ------------------------------- |
| `runtime/apps/{app_name}.log`       | 应用标准输出 + 错误输出 | 进程 stdout/stderr 合并流式追加 |
| `runtime/forum/latest.log`          | 论坛最新运行日志        | 覆盖式最新，另存历史            |
| `runtime/forum/history/{date}.json` | 按日期归档的历史日志    | `date` 格式 `YYYY-MM-DD`        |
| `outputs/{app_name}/latest.txt`     | 应用最近一次文本输出    | 应用正常退出时由进程管理器写入  |

**论坛历史日志条目结构**（`{date}.json` 为数组）：

```json
[
  {
    "time": "2026-08-26T09:00:12+08:00",
    "event": "collect",
    "message": "采集到帖子 12 条",
    "task_status": "running"
  }
]
```

### 6.3 `reports/{report_id}/report.md` — 结构化分析报告

Markdown 文本，固定八段结构（见第 10 节），`report_id` 生成规则：`{主题词拼音缩写}_{YYYYMMDDHHmmss}`，确保唯一且可读。

### 6.4 `graphs/{report_id}/graph.json` — 图谱数据

```json
{
  "report_id": "mcp_2026082609000",
  "meta": { "generated_at": "2026-08-26T09:05:00+08:00", "topic": "某主题" },
  "nodes": [
    { "id": "n1", "label": "事件A", "type": "event", "source_ref": "news:xxx" },
    { "id": "n2", "label": "机构B", "type": "org",  "source_ref": "internal_data:yyy" }
  ],
  "edges": [
    { "id": "e1", "source": "n1", "target": "n2", "type": "published_by", "source_ref": "news:xxx" }
  ]
}
```

**节点类型**（`node.type`）：`topic` 主题、`person` 人物、`org` 机构、`event` 事件、`source` 来源、`keyword` 关键词。
**关系类型**（`edge.type`）：`mentions` 提及、`related_to` 相关、`published_by` 发布、`sourced_from` 来源引用。

### 6.5 文件并发安全

`store.py` 提供带文件锁的读写工具：

- **JSON 读写**：`read_json(path)` / `write_json(path, data)` — 写入时使用 `filelock` 库加锁（跨进程安全），写入先写临时文件再原子 `os.replace()`。
- **日志追加**：`append_log(path, line)` — 加锁追加，避免多进程/协程交叉写入。

> 若不愿引入 `filelock` 依赖，可用 `asyncio.Lock` 实现进程内锁（适用于单 Uvicorn 进程场景）。

### 7.2 进程管理模块（核心）

单功能应用以 `python apps/{app_name}_app.py` 子进程运行，由 `ProcessManager` 统一管理。

**应用状态机**：

```
            start               running            stop
stopped ─────────▶ starting ─────────▶ running ─────────▶ stopping ─────────▶ stopped
   ▲                                            │
   └──────────────────── failed ◀───────────────┘  (进程异常退出)
```

**ProcessManager 接口**

```python
class ProcessManager:
    async def start(self, app_name: str) -> bool      # 启动子进程
    async def stop(self, app_name: str) -> bool       # 停止子进程
    def status(self, app_name: str) -> str            # 查询状态
    async def read_output(self, app_name: str) -> str # 读最近输出
    async def read_log(self, app_name: str, tail=200) # 读日志尾部
    def all_status(self) -> dict[str, str]            # 全部应用状态
```

**关键实现要点**

```python
import asyncio
import sys
from pathlib import Path

class AppProc:
    """子进程运行时上下文"""
    __slots__ = ("proc", "status", "log_f", "pump_task")

    def __init__(self, proc, status, log_f, pump_task):
        self.proc = proc
        self.status = status
        self.log_f = log_f      # 日志文件句柄
        self.pump_task = pump_task  # 输出泵协程任务

async def _launch(self, app_name: str):
    log_path = DATA_ROOT / "runtime" / "apps" / f"{app_name}.log"
    log_path.parent.mkdir(parents=True, exist_ok=True)
    log_f = open(log_path, "a", encoding="utf-8")

    proc = await asyncio.create_subprocess_exec(
        sys.executable, str(APPS_DIR / f"{app_name}_app.py"),
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.STDOUT,   # 错误合并进标准输出
        cwd=str(BACKEND_DIR),
    )

    async def _pump():
        try:
            async for line in proc.stdout:
                text = line.decode("utf-8", errors="ignore")
                log_f.write(text)
                log_f.flush()
                await ws_manager.broadcast({
                    "type": "app_output",
                    "data": {"app_name": app_name, "output_text": text}
                })
        except asyncio.CancelledError:
            pass  # 停止时主动取消，正常退出
        finally:
            log_f.close()  # 确保文件句柄释放
            # 进程退出后：写 latest.txt，判定 failed/stopped
            await proc.wait()
            exit_code = proc.returncode
            new_status = "failed" if exit_code != 0 else "stopped"
            self._update_status(app_name, new_status)
            if exit_code == 0:
                await self._save_latest_output(app_name)

    pump_task = asyncio.create_task(_pump())
    self._procs[app_name] = AppProc(proc=proc, status="running", log_f=log_f, pump_task=pump_task)
```

> **停止策略**：`stop()` 置状态为 `stopping`，向子进程发送终止信号（Windows `proc.terminate()`，POSIX `proc.send_signal(signal.SIGTERM)`），等待最多 5 秒后若未退出则 `proc.kill()`；停止后保留已生成输出与日志。

> **资源清理**：`_pump` 协程在 `finally` 中关闭 `log_f`，避免文件句柄泄漏；应用停止时取消 `_pump_task` 确保协程退出。

### 7.3 检索分析模块

主题检索流程：`query` + `source_types` → 并行采集三方向数据 → 内容分析（观点抽取、情绪判定）→ 洞察生成 → 汇总为 8 段式报告，并生成图谱。

**情绪倾向**：正向 / 中性 / 负向三分类。当前 `sentiment_mode=rule_based`（规则词典），预留 `llm` 模式接口，便于后续接大模型。

### 7.5 WebSocket 实时协议

- 连接地址：`/ws`
- 消息统一信封：`{ "type": string, "data": object, "ts": number }`

| type            | data 字段（必含）               | 触发时机     |
| --------------- | ------------------------------- | ------------ |
| `app_status`    | `app_name`, `status`            | 应用状态变更 |
| `app_output`    | `app_name`, `output_text`       | 应用有输出流 |
| `forum_log`     | `message_text`, `task_status`   | 论坛日志新增 |
| `system_status` | `system_status`, `running_apps` | 系统状态变化 |
| `graph_ready`   | `report_id`, `graph_path`       | 图谱生成完成 |
| `error`         | `module_name`, `error_message`  | 任意模块出错 |

**`WebSocketManager`**：维护 `set[WebSocket]` 连接集合，`broadcast(message)` 向所有连接推送；可选按 `app_name`/`report_id` 订阅过滤（首版可全量广播，简单可靠）。

**心跳与超时**：服务端每 30 秒发送 `{"type": "heartbeat"}` ping，客户端收到后回复 `{"type": "heartbeat_ack"}`；若 60 秒无响应则服务端主动断开，由客户端重连逻辑恢复。

## 8. 错误处理策略

| 场景               | 处理方式                                                              |
| ------------------ | --------------------------------------------------------------------- |
| 子进程异常退出     | `_pump` 检测 `returncode != 0`，置状态 `failed`，广播 `error` 消息    |
| REST 请求参数错误  | Pydantic 校验自动返回 422 + 字段级错误详情                             |
| 文件读写失败       | `store.py` 捕获 `IOError`，日志记录，API 返回 `code=500` + 错误消息   |
| WebSocket 断连     | 客户端自动指数退避重连，服务端无感知                                   |
| 配置文件损坏       | `config.py` 加载失败时回退到内置默认值 + 日志警告                     |
| 图谱/报告不存在    | API 返回 `code=404`，`message: "资源不存在"`                          |
| 应用重复启动       | 检测当前状态，若非 `stopped`/`failed` 则拒绝，返回 `code=409`         |

**统一异常中间件**：

```python
@app.exception_handler(Exception)
async def global_exception_handler(request, exc):
    logger.exception("未处理异常")
    return JSONResponse(
        status_code=500,
        content={"code": 500, "message": f"服务内部错误: {type(exc).__name__}", "data": None}
    )
```

### 10.4 WebSocket 客户端封装

```typescript
// composables/useWebSocket.ts
import { ref } from 'vue'

interface WsMessage {
  type: string
  data: Record<string, unknown>
  ts?: number
}

export function useWebSocket(url: string) {
  const connected = ref(false)
  let ws: WebSocket | null = null
  let retryCount = 0
  const MAX_RETRY = 10
  let retryTimer: ReturnType<typeof setTimeout> | null = null

  function dispatch(msg: WsMessage) {
    // 按 type 分发到各 Pinia Store
    // app: app_status, app_output
    // system: system_status, error
    // forum: forum_log
    // graph: graph_ready
  }

  function connect() {
    ws = new WebSocket(url)

    ws.onopen = () => {
      retryCount = 0
      connected.value = true
    }

    ws.onmessage = (e) => {
      const msg: WsMessage = JSON.parse(e.data)
      if (msg.type === 'heartbeat') {
        ws?.send(JSON.stringify({ type: 'heartbeat_ack' }))
        return
      }
      dispatch(msg)
    }

    ws.onclose = () => {
      connected.value = false
      if (retryCount < MAX_RETRY) {
        // 指数退避：1s, 2s, 4s, 8s, ... 上限 30s
        const delay = Math.min(1000 * Math.pow(2, retryCount), 30000)
        retryCount++
        retryTimer = setTimeout(connect, delay)
      }
    }

    ws.onerror = () => {
      // onclose 会随后触发，此处仅记录
    }
  }

  function disconnect() {
    if (retryTimer) clearTimeout(retryTimer)
    retryCount = MAX_RETRY  // 阻止自动重连
    ws?.close()
    ws = null
  }

  function send(msg: Record<string, unknown>) {
    ws?.send(JSON.stringify(msg))
  }

  return { connected, connect, disconnect, send }
}
```

| 规则                                                       | 落地方式                                                     |
| ---------------------------------------------------------- | ------------------------------------------------------------ |

| 报告结论可追溯到来源/论坛记录/图谱节点                     | 报告「重点证据」段带 `source_ref` 引用，图谱 `edge.source_ref` 关联 |

## 12. 报告输出格式（8 段式）

`report.md` 固定结构，由 `report_service` 拼装：

| 段落     | 内容                           |
| -------- | ------------------------------ |
| 事件概述 | 主题背景 + 分析范围            |
| 时间线   | 按时间排序的关键事件           |
| 传播渠道 | 按来源类型统计传播分布         |
| 主要观点 | 不同来源/角色的核心观点        |
| 情绪倾向 | 正向 / 中性 / 负向整体判断     |
| 风险判断 | 高风险点 + 关注事项            |
| 重点证据 | 来源标题、链接、摘要、引用位置 |
| 结论摘要 | 最终结论 + 建议                |
